本页面是教导玩家通过FCS对小队进行修改的指南。

Attributes（属性）
Base（基底）

Name（名称）: 此处显示该条目在游戏和FCS中的名称。

Object Type（对象类型）：该类条目的类型为 CHARACTER（角色）。通常无法更改。

String ID（字符串 ID）: 每个条目都有自己独一无二的 String ID 作为标识符，不同条目的 String ID 绝不能相同。

String ID 能让玩家识别条目来源于何处。一般情况下玩家无需修改 String ID 。

General
animal age random:0~1，影响动物年龄
dont mutiply:小队的队员数量是否会被小队规模乘数影响
dont multiply设置为True的小队不会被影响，比如很多酒吧、商店的店主小队、 蒙格勒（城镇）的部分居民小队等
小队模板中显式设置的leader不受小队规模乘数影响，数量始终为1
但是，不是所有小队都显式地设置了leader，若没有设置，游戏会在队员角色生成后选择队长，也就是说此类角色的生成时候已经受到了小队规模乘数的影响。
特殊角色作为小队队员的时候，如果有生成多个此角色的尝试，会改为生成其独特替代生成，详细机制请参考特殊角色页面
比如，菲尼克斯的宝座小队，dont multiply为False，会受到小队规模乘数的影响，火焰守护者是队员，生成多个此角色时候会尝试生成独特替代生成。火焰守护者是唯一独特生成替代为自己的特殊角色，因此也是正常情况下唯一能够同时出现多个的特殊角色
小队模板中，大多数队员角色的引用域（比如squad、animal、squad2）等都设置了数量的最小值（下称min）和最大值（下文称为max）。但是这些最值的意义并不直接。
max为0，则不随机地生成min数量的此角色
否则，会取max和min的中间某值，乘以小队规模乘数，作为此角色项目的生成数量

References（引用）

faction：在小队层面设置的派系归属。实际上在游戏中，一个角色所在的派系决定优先级如下：

所在的小队如果作为城镇居民/酒吧小队生成：优先使用小队层面的派系，如果没有，则使用城镇的派系
所在的小队如果作为野外小队生成：优先使用小队层面的派系。如果没有，则使用野生动物派系
所在的小队作为其他小队的housemate（室友）生成，则此小队直接使用引用它的小队最后决定的派系归属。
所在的小队作为其他小队的slave（奴隶）生成，则优先使用此小队本身的派系归属，否则使用引用者的派系。

personality：小队层面设置的个性，但是小队层面设置的个性不会实现。实际上在游戏中，一个角色所在的个性决定优先级如下：

如果有角色层面设置的个性，优先使用
否则，如果所属的派系有默认个性分布，则使用
否则，随机决定
小队层面设置的个性不会实现
只会使用列表中的第一个值。因此，想要实现多个个性中随机的效果，需要放在一个个性项目里被引用，而不是在此域的列表内添加多个个性项目。

dialogue packages：小队层面设置的对话包。列表的多个项目会同时生效。游戏中角色实际使用的对话包优先级非常复杂：

小队层面、角色层面都可以设置对话包。小队层面设置的对话包覆盖分为队长对话覆盖（dialog leader）和队员对话覆盖（dialog squad）两项。
正常情况下，队长对话包会覆盖队长角色模板设置的对话包，队员对话包会覆盖队员角色模板设置的对话包。
不是所有小队模板都有队长对话覆盖/队员对话覆盖项目。
如果小队模板没有队长对话覆盖，队长将会使用其角色模板层面设置的对话。
如果小队模板没有队员对话覆盖，则使用队员角色自身的角色模板的对话。
覆盖的部分是角色模板的 dialogue package项 而非 dialogue 项
但是，任何小队的队员被分离出来之后会发生小队分离，成为一支新的小队的队长，此时他使用的对话将会是小队的队长对话覆盖（如果小队层面没有设置队长对话包的话，会使用角色自己的对话包），而不是队员对话覆盖。也就是说，只要队员分离出来，那么队员对话覆盖并不能覆盖队员的角色对话包，要么会使用队长的对话覆盖（如果有的话），要么会使用角色自己的对话包。
当已经被分离的角色被带回原小队附近的时候，就会恢复作为原小队成员的身份，重新使用队员对话包，（如果此小队没有队员对话包那么会使用角色自身的对话包）。原队长重新加入后会变成队员。此时使用的将会是小队设置的队员对话包（如果此小队没有队员对话包那么会使用角色自身的对话包）。理论上，对于单角色小队，无论如何分离合并，此角色必定都为队长，此时可以利用某些奴隶角色会主动加入打败奴隶主的角色的小队的特点，使其成为多角色小队，从而利用小队分离和合并使得原队长以队员身份重新加入
