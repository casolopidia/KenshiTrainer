条件的基本结构

FCS 中的普通对话条件可概括为：

condition = {
    condition_name,   // 选择 DC_* 条件
    compare_by,       // =、< 或 >
    who,              // ME、TARGET 等判断对象
    value             // 数值阈值或布尔期望值
};
ID 决定使用哪个 DC_* 条件。
who 指定普通条件的起始角色：T_ME 选择 ME，其他值统一选择 TARGET。部分条件会忽略 who，固定读取 ME、TARGET、小队、城镇或玩家阵营数据。
value 对数值条件是阈值；对布尔条件则通常只看正负。
同一条对话中的普通条件通常按 AND 组合：任意一个条件失败，该行就不会通过。
Race、Faction、Personality 等独立列表通常在同一类别内按 OR、不同类别之间按 AND 处理。
新版的 FCS 能搜索所有应用了某对话条件的对话。使用“condition name = X”在“Everything”处进行搜索，X 是该条件对应的数值。
对话判断角色

尽管枚举类型与 speaker 相同，普通条件中的 who 实际只区分两种情况：

if (who == T_ME)
    checkedCharacter = ME;
else
    checkedCharacter = TARGET;

因此：

T_ME：选择 ME。
其他所有值：选择 TARGET。
部分对话事件会依次尝试不同的玩家角色作为 TARGET；任意一名角色独立通过整组条件时，对话即可触发。
比较符并不统一
类型	条件	实际含义
严格数值比较	ID 10=DC_FACTION_RANK、12=DC_PLAYER_TECH_LEVEL、13=DC_NUM_DIALOG_EVENT_REPEATS、35=DC_SQUAD_SIZE、37=DC_NUM_BACKPACKS、73=DC_TOWN_LEVEL_CURRENT_LOCATION、74=DC_PLAYERS_BEST_TOWN_LEVEL	=、<、> 分别是严格的 ==、<、>。
门槛数值比较	ID 1=DC_RELATIONS、2=DC_PLAYERMONEY、3=DC_REPUTATION、18=DC_TARGET_LAST_SEEN_X_HOURS_AGO、40=DC_BOUNTY_AMOUNT_PERCEIVED、47=DC_BOUNTY_AMOUNT_ACTUAL	只有 < 是严格小于；= 与 > 都表示 >=。
布尔条件	大多数状态条件	比较符通常被忽略；value > 0 要求为真，value <= 0 要求为假。
特殊掩码	ID 23=DC_HAS_TAG、26=DC_PERSONALITY_TAG	在普通数值条件循环之外整理成必须拥有／必须排除的位掩码。
失效或废弃	ID 0=DC_NONE、6=DC_FACTION_VARIABLE、15=DC_IMPRISONMENT_IS_DEATHROW、34=NULL_NULL_____DC_TARGET_SQUAD_SIZE	无正常业务判断，不应在新 Mod 中使用。

精确等于门槛值的写法：对于门槛数值条件，要判断恰好等于 N，可同时添加 = N 与 < N+1。

Stronger_Than_Me

中文名称： 目标明显强于我

内部名： DC_STRONGER_THAN_ME
ID： 22
条件类型： 布尔条件
作用： 检查 TARGET 的内部战斗强度是否大于 ME 的 1.5 倍。
判断角色： 固定比较 ME 与 TARGET；who 不参与。
数据来源： 双方 StateBroadcastData 中缓存的战斗强度值。
强度构成： 战斗强度由当前力量、攻击侧战斗值和防御侧战斗值取平均。力量及战斗值会受到伤势、装备修正和当前持械／徒手状态影响。对非动物角色，如果当前没有装备武器，最终战斗强度会乘以 0.1；动物不受这项修正。
判断公式： TARGET强度 > ME强度 × 1.5
使用提示： 该条件不是分别比较力量、武术或武器。双方会先各自计算一个综合值，再进行比例比较。
边界说明： 使用严格大于判断。TARGET 恰好等于 ME 的 1.5 倍时仍为假。
combatStrength = (current_strength + current_attack + current_defence) / 3.0;


if (!character->isAnimal() && !character->inventory->hasWeaponEquipped())
    combatStrength *= 0.1;
