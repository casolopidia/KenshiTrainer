本页面部分内容来自 Character (FCS) 与 fcs.def 文件（位于游戏目录）。

本页面是教导玩家通过FCS对角色进行修改的指南。

Attributes（属性）
Base（基底）

Name（名称）: 此处显示该条目在游戏和FCS中的名称。

Object Type（对象类型）：该类条目的类型为 CHARACTER（角色）。通常无法更改。

String ID（字符串 ID）: 每个条目都有自己独一无二的 String ID 作为标识符，不同条目的 String ID 绝不能相同。

String ID 能让玩家识别条目来源于何处，例如阿格努来自 rebirth.mod ，而艾萨塔，石魔来自 Dialogue.mod 。一般情况下玩家无需修改 String ID 。
bounty（赏金）

assigns bounties（指派赏金）: 若此栏值为 True ，则该角色拥有发布赏金的能力。例如龙恩，玩家犯罪时若被他看见，则会被他挂上赏金。这是一个无效项，角色发布赏金的充要条件是：

所属派系不是伪派系
NPC class为OT_LAW_ENFORCEMENT或者OT_MILITARY

bounty amount（悬赏金额）: 在此处填写该角色拥有的赏金数目。

bounty amount fuzz（悬赏金额波动）: 随机化赏金的大小，注意实际赏金是 bounty amount + bounty amount fuzz ，且该值为负数时等效于0。

例如砂之老大的 bounty amount = 2000 ， bounty amount fuzz = 1000 ，砂之老大的实际赏金为2000~3000 。



bounty chance（悬赏概率）: 在此处填写该角色被悬赏的概率。

General（常规）

body（捏人数据）: 此角色的身体形状/数据。例如阿格努的此栏为.\data\character\bodies\Agnu.bod2 。留空为随机身体。捏人界面导出捏人数据，得到的 .bod2 文件可以用于此处。

dumb（哑巴）: 该值为 True 时，此角色无法使用对话，除非对话专门调用该角色。例如阿格努。

faction importance（派系重要性）:此角色相关的任何行动对派系关系的影响。数值越大，治疗或囚禁（或其他操作）该角色影响的派系关系就越大。

例如平民设置低，贵族或外交官设置高（像天狗皇帝这样的贵族该值为 100）。从本质上讲，这表达了这个角色对其派系的重要性。



mesh（网格）: 此角色的模型/网格。留空为随机模型/网格。Fandom 的相关页面认为此栏值没有产生效果，建议使用 body（捏人数据）替代。

levels（等级）

armour grade（护甲等级）: 设置该角色所穿护甲的等级/品质。

GEAR_PROTOTYPE - [等级模本]，GEAR_CHEAP - [等级赝品]，GEAR_STANDARD - [等级标准]，GEAR_GOOD - [等级高]，GEAR_QUALITY - [等级专家]，GEAR_MASTER - [等级杰作]。



armour upgrade chance（护甲升级几率）: 角色所穿护甲高于 armour grade 所设品质的概率。

例如伯恩的护甲品质正常为[等级赝品]，但有5%概率为[等级标准]。



combat stats（战斗属性）: 如果未设置 stats 域，这将决定战斗相关技能的等级(优先级最低)。

力量、韧性、敏捷、暗杀（该值 x0.5）、近战攻击、近战防御、躲闪（该值 x0.1）、武术（该值 x0.1）、奔跑、游泳、武器技能（武士刀等）、战地医生、炮塔、精准射击。



ranged stats（远程属性）: 如果未设置 stats 域，这将决定远程相关技能的等级。（覆盖 combat stats 给出的相关数据）

知觉、炮塔、十字弩、精准射击。



stats randomise（属性随机值）: 在此处填写该角色属性随机值的大小（随机值的大小也会受种族乘数的影响）。

例如精英猎人此数据为5，理论力量为75，实际力量为70~80。再例如无敌五人组此数据为5，理论力量为75，实际力量为77~88。
影响除暗杀、科学、十字弩工匠、劳动、耕作、烹饪以外的所有技能。



stealth stats（潜行属性）: 如果未设置 stats 域，这将决定该角色潜行相关技能的等级。（覆盖 combat stats 给出的相关数据）

敏捷、潜行、撬锁、偷窃、暗杀、战地医生。



strength（力量）: 如果未设置 stats 域，这将决定该角色力量的等级（覆盖 combat stats 给出的力量）。

unarmed stats（徒手属性）: 如果未设置 stats 域，这将决定该角色徒手技能的等级。（覆盖 combat stats 与stealth stats 给出的相关数据）

敏捷、躲闪、武术。
money（钱）

money item max（最大数量的实体开币）:角色库存中能拥有的最大开币（物品）数量。

money item min（最小数量的实体开币）: 角色库存中能拥有的最小开币（物品）数量。

money item prob（持有实体开币概率）: 拥有开币（物品）的概率[0-1]。

money max（最大金钱）: 该角色生成时拥有的能在
商店柜台
进行购买的最大金额。像 wages 一样有效。在库存中不可见。

money min（最低金钱）: 该角色生成时拥有的能在
商店柜台
进行购买的最低金额。像 wages 一样有效。在库存中不可见。无效项目

商店柜台
进行购买。Fandom相关页面认为 wages 一栏破损，无法正常发挥作用。Fandom是对的，wage并不会每天发钱，但是此项目仍有实际作用。作用方法详见库存生成和队伍资金

tags（标签）

is trader（这是否是商人）: 此值只会影响非城镇居民（酒吧小队、野外小队）。请参考库存生成和队伍资金

NPC class（NPC 类型）: NPC 的分类，让不同的 NPC 相互识别。一旦 NPC 被玩家招募，NPC Class 将无效。可招募条件会限制部分的 NPC Class 。此外，还调控一些其他机制，如发布悬赏的能力等。

OT_NONE - 无
OT_LAW_ENFORCEMENT - 执法者
OT_MILITARY - 军事人员
OT_TRADER - 商人
OT_CIVILIAN - 市民
OT_DIPLOMAT - 使该角色拥有外交状态
OT_SLAVE - 奴隶
OT_SLAVER - 奴隶贩子
OT_BANDIT - 土匪
OT_ADVENTURER - 冒险家
OT_END - 游戏中没有拥有此值的角色。
type（类型）

female chance（女性几率）: 此角色为女性的几率。

named（随机名字）: 如果为 True，则该角色从名称列表中随机选择名称。否则，将使用 Name 一栏的值。

shaved（头发剃光）: 这个角色的头发是否像奴隶一样剃光。对于沙克族来说，这将导致他们被断角。

slave（初始奴隶状态）: NOT_SLAVE - 不是奴隶，IS_SLAVE - 奴隶，ESCAPING_SLAVE - 逃跑的奴隶，EX_SLAVE - 前奴隶。

unique（特殊角色）: 通常情况下此角色只会生成一次。若该角色死亡，可以通过导入找回。当且仅当一个特殊角色的 unique replacement respawn 被设置为自身时，特殊角色可以在游戏中同时存在多个，例如火焰守护者。

wears uniform（派系制服）: 这个角色的服装被认为是派系制服。如果玩家角色的该栏值为 True，则其服装将成为玩家派系的一部分。

faction：在角色层面设置的派系归属。实际上在游戏中，角色层面设置的派系归属不会实现。一个角色所在的派系决定优先级如下：

所在的小队如果作为城镇居民/酒吧小队生成：优先使用小队层面的派系，如果没有，则使用城镇的派系
所在的小队如果作为野外小队生成：优先使用小队层面的派系。如果没有，则使用野生动物派系
所在的小队作为其他小队的housemate（室友）生成，则此小队直接使用引用它的小队最后决定的派系归属。
所在的小队作为其他小队的slave（奴隶）生成，则优先使用此小队本身的派系归属，否则使用引用者的派系。

personality：角色层面设置的个性。实际上在游戏中，一个角色所在的个性决定优先级如下：

如果有角色层面设置的个性，优先使用
否则，如果所属的派系有默认个性分布，则使用
否则，随机决定
小队层面设置的个性不会实现
只会使用列表中的第一个值。因此，想要实现多个个性中随机的效果，需要放在一个个性项目里被引用，而不是在此域的列表内添加多个个性项目。

dialogue packages：角色层面设置的对话包。列表的多个项目会同时生效。游戏中角色实际使用的对话包优先级非常复杂：

小队层面、角色层面都可以设置对话包。小队层面设置的对话包覆盖分为队长对话覆盖（dialog leader）和队员对话覆盖（dialog squad）两项。
正常情况下，队长对话包会覆盖队长角色模板设置的对话包，队员对话包会覆盖队员角色模板设置的对话包。
不是所有小队模板都有队长对话覆盖/队员对话覆盖项目。
如果小队模板没有队长对话覆盖，队长将会使用其角色模板层面设置的对话。
如果小队模板没有队员对话覆盖，则使用队员角色自身的角色模板的对话。
覆盖的部分是角色模板的 dialogue package项 而非 dialogue 项
但是，任何小队的队员被分离出来之后会发生小队分离，成为一支新的小队的队长，此时他使用的对话将会是小队的队长对话覆盖（如果小队层面没有设置队长对话包的话，会使用角色自己的对话包），而不是队员对话覆盖。也就是说，只要队员分离出来，那么队员对话覆盖并不能覆盖队员的角色对话包，要么会使用队长的对话覆盖（如果有的话），要么会使用角色自己的对话包。
当已经被分离的角色被带回原小队附近的时候，就会恢复作为原小队成员的身份，重新使用队员对话包，（如果此小队没有队员对话包那么会使用角色自身的对话包）。原队长重新加入后会变成队员。此时使用的将会是小队设置的队员对话包（如果此小队没有队员对话包那么会使用角色自身的对话包）。理论上，对于单角色小队，无论如何分离合并，此角色必定都为队长，此时可以利用某些奴隶角色会主动加入打败奴隶主的角色的小队的特点，使其成为多角色小队，从而利用小队分离和合并使得原队长以队员身份重新加入


backpack（背包）: 该角色生成时携带的背包。

blueprints（蓝图）: 此角色生成时存在于物品栏中的蓝图。此处的蓝图不能像库存清单的蓝图一样直接引用装备项目，只能直接引用研究项目，由研究解锁对应的事物。

bounty Factions（悬赏派系）: 如果这个角色拥有赏金，此列表下的派系将逮捕TA。如果角色拥有赏金但此列表没有引用条目，则该角色默认被联合城悬赏。

color（染色）: 这里的值将覆盖派系的配色方案。但如果护甲本身存在配色方案，则不会覆盖，例如贵族长袍。


death items（死亡物品）: 如果从活着、昏迷的角色的物品栏中移除，他们将立即被杀死。若在角色清醒时拿走则不会死亡。

shopping（购物）: 该角色将在
商店柜台
购买的物品类型。该值引用物品功能（item function）的值，而不是特定物品。

val0是购买数量；val1是购买概率（0~100）；val2是购买物品的优先级，0最高，1次之，2再次之等。
例如：如果一个角色的清单上有面包，他们可以购买所有食物。
详情请参阅NPC购物机制。

stats（属性统计）: 这将决定角色的属性值（优先级最高，覆盖 combat stats、ranged stats、stealth stats、strength、unarmed stats 的值），stats randomise 在使用 stats 后依然能进行属性随机化。

weapon level（武器等级）: 角色生成时所持有的武器的等级。此值为制造者，然后随机选择该制作者下属的模型。

例如此值选择刃行者，武器品质会在[模型 # 刃之一]、[模型 # 刃之二]、[模型 # 刃之三]中随机选择。
没有办法直接设置[模型 # 刃之三]，显然游戏开局#圣剑的开局武器一定为[模型 # 刃之三]是错误的。
如果该角色 weapons 一栏有值，但 weapon level 没有引用条目，则武器制造者为古人。
val0是相对概率。

weapons（武器）: 角色生成时所持有的武器。
