# Kenshi 内置修改器 · 构建与安装说明

## 一、成果物

```
mods/KenshiTrainer/
├── KenshiTrainer.dll    ← 编译好的插件（x64 Release, v100 工具链）
├── KenshiTrainer.mod    ← 让 mod 出现在 Kenshi 启动器 Mods 列表
└── RE_Kenshi.json       ← 声明插件 DLL
```

源码在 `src/`（KenshiTrainer.cpp 单文件 + 自动生成的两个字符串头）。

## 二、安装到游戏

前置：已安装 **RE_Kenshi v0.3.5+**（见 docs/03，安装成功标志=主菜单显示版本号）。

1. 把 `mods/KenshiTrainer` 整个文件夹复制到 `Kenshi安装目录/mods/` 下。
2. 启动 Kenshi 启动器，在 Mods 页勾选 **KenshiTrainer**，正常进游戏。
3. 若加载失败闪退，检查 Windows 的"智能应用控制(Smart App Control)"是否拦截了插件 DLL。

依赖说明：插件需要 `MSVCR100.dll / MSVCP100.dll`（VC++ 2010 运行库）。
Kenshi 游戏目录自带；个别精简系统若缺失，安装 VC++ 2010 x64 Redistributable 即可。

## 三、使用

- 游戏内左上角有蓝色 **「修改器」** 悬浮按钮：
  - **单击**：打开/关闭修改器主面板
  - **长按拖动**：移动按钮位置（位置保存在 `mods/KenshiTrainer/KenshiTrainer.ini`）
- 主面板两个页签：
  - **属性**：显示当前选中角色的 38 项技能，输入数值点「设定」（或在输入框按回车）即改；
    「全部拉满」一键全部 100；「刷新」重新读取。
  - **物品生成**：分类（全部/武器/护甲/物品/弩/背包容器）+ 名称搜索，
    列表含**所有启用 mod 新增的物品**；选中后填数量点「生成到背包」，双击列表项也可生成。
    背包满时物品会掉落在角色脚边（不会消失）。
  - **图标预览**：选中列表中的物品后，右侧显示游戏内真实图标——
    有自定义图标文件的物品直接读取该文件；其余用游戏自己的图标渲染管线
    （临时创建一个物品实例，调用 `InventoryIcon::createIconImage`），
    武器/护甲的图标会随当前选择的制造商/模型/品质变化。
  - **品质与材质**（武器/护甲）：
    - 武器：「制造商」按钮循环切换制造者（十字/铭刃/联合城等，自动从该武器的
      引用列表读取），「模型」按钮循环切换品质模型（生锈的垃圾~铭物）。
    - 护甲：「品质」按钮循环切换材质等级（原型/赝品/标准/高/专家/杰作）。
    - 两个选项默认为「自动」（游戏默认品质）。选项来自物品 GameData 的引用列表，
      按引用类型自动分类（WEAPON_MANUFACTURER → 制造商；MATERIAL_SPECS_* → 模型/品质），
      对 mod 物品同样有效。
    - 生成后状态栏会回读实际生成的 [manufacturer=… material=… lv=…]，用于确认参数映射是否正确。
- 注：主菜单下入口按钮也会显示（初版曾 hook TitleScreen::show 来隐藏，实测会导致崩溃，已移除）。

## 四、本机开发环境（已验证可复现）

| 组件 | 来源 |
|---|---|
| VS2022 BuildTools（MSBuild 宿主） | 已装 |
| **VC++ 2010 (v100) x64 编译器** | Windows SDK 7.1 ISO (`GRMSDKX_EN_DVD.iso`) 中的 `Setup/vc_stdx86.msi` + `vc_stdamd64.msi`，`msiexec /qn` 直接装（需管理员） |
| Windows SDK 7.1 头/库 | 同 ISO 的 `WinSDK_amd64.msi` + `WinSDKBuild_amd64.msi`（后者注册 v100/Windows7.1SDK 平台工具集） |
| 注册表修正 | `tools/fixreg.ps1`：补 `VisualStudio\10.0\Setup\VC|VS ProductDir` 与 `Microsoft SDKs\Windows\v7.0A InstallationFolder` |
| KenshiLib + MyGUI + Ogre + Boost 1.60 | `reference/KenshiLib_Examples_deps`（git clone 后解出 boost.zip） |

两个编译修正已固化在 `KenshiTrainer.vcxproj`：`TrackFileAccess=false`
（新版 MSBuild tracker 与 v100 不兼容，否则报 `Required file "" is missing`）、
`GenerateManifest=false`（否则 Mt 任务报 `mt.exe unexpectedly not a rooted path`）。

重新编译：

```powershell
powershell -ExecutionPolicy Bypass -File tools\build.ps1
```

（会编译并自动把 DLL 复制进 mods/KenshiTrainer/）

## 五、首次进游戏需要实测确认的清单

这些点在逆向头文件里语义不完全明确，**首次运行后请反馈结果**以便修正：

1. 物品生成参数映射：武器用 `createItem(gd, handle, 模型, 制造商, -1, null)`，
   护甲用 `createItem(gd, handle, null, 材质等级, -1, null)`。若生成结果与选择不符，
   看状态栏回读的 manufacturer/material 字段即可确定正确映射并调整一行代码。
2. 图标预览：显式 icon 字段的物品直接读文件；auto icon 物品走 createIconImage。
   临时预览实例在下一次预览/关闭窗口时通过 `ou->destroy` 销毁。若预览导致异常，
   RE_Kenshi 日志会有 "icon failed" 记录。
2. UI 皮肤：插件启动时会把游戏里全部 MyGUI 皮肤名写入 RE_Kenshi 日志
   （`KenshiTrainer skins: ...`），输入框/列表的实际皮肤按关键字自动匹配；
   若某个控件外观异常，把日志里这段发我即可精确修正。
3. 中文显示：建议游戏语言设为简体中文（依赖游戏内 CJK 字体）。
4. 属性写入后被游戏经验系统回写的情况（如发生，需要加 hook 处理）。

## 六、已知边界

- 属性修改直接写基础值（0~100000），不做游戏内平衡校验。
- 物品列表上限显示 2000 条（超大 mod 合集下用搜索过滤）。
- 卸载：删除 `mods/KenshiTrainer` 文件夹即可，无副作用。

## 八、ImGui 版（2026-09-15 重构）

**架构改为 ImGui 叠加层，完全独立于 Dust 和 MyGUI**：
- 插件注册为 **PreloadPlugin**（先于渲染器加载），hook
  `d3d11!D3D11CreateDeviceAndSwapChain` + `dxgi!CreateDXGIFactory/1/2`
  → 补工厂 vtable 的 `CreateSwapChain`(10)/`CreateSwapChainForHwnd`(15)
  → 捕获 swapchain 后补其实例 vtable 的 `Present`(8)。全程 KenshiLib AddHook（多插件兼容）。
- 输入：swapchain 描述拿到游戏 HWND → SetWindowLongPtr 挂 WndProc → ImGui 吸收键鼠
  （菜单捕获输入时吞掉对应消息，不再传给游戏）。
- ImGui 1.86（最后一个兼容 VS2010 的版本线）静态编译进 DLL；
  `imgui_impl_dx11.cpp` 改为动态加载 D3DCompiler_47/43（SDK 7.1 无 d3dcompiler.h，
  ID3DBlob 手工声明）；中文字体用系统微软雅黑（msyh.ttc，回退 simsun.ttc）。
- 窗口位置由 ImGui 自己持久化到 KenshiTrainer_imgui.ini。
- 入口：左上角「修改器」小窗口（拖标题栏移动），按钮开关主面板。
- 主面板原生支持：标题栏拖动、X 关闭、滚动条、输入框、下拉框。
- 物品图标预览在 ImGui 版暂时移除（需要 Ogre→D3D11 纹理桥接，后续可做）。
- 已知边界：Kenshi 用 OIS 读输入，WndProc 吞消息可能无法完全阻止游戏响应菜单上的点击
  （ Dust 同款方案的常见边界），实测若有问题再处理。
