# 武器品质与存档序列化（存档后品质回退问题的结论）

> 2026-09-21 基于本机真实存档（`AppData\Local\kenshi\save\nv2222`）二进制分析确认。
> **修复已于同日打入 `src/KenshiTrainer.cpp`（CreateWeaponRobust）并编译部署。**

## 一、问题现象

修改器生成的武器在游戏内显示品质正常（如刃行者/铭刃），**存档再读档后品质回退为「开顿城1号」**（Catun No.1，游戏默认制造者的默认型号）。

## 一点五、最终定位的根因（存档取证结论）

对全部存档（11 / nan11 / nv2222 及 zone 文件）的物品记录取证后确认：
健康武器记录 = `material sid`（型号）+ `level`（**该型号在其制造者下登记的等级**），
`company sid` 通常为空。读档时游戏按 **(制造者, level)** 反查型号——

旧代码两个致命不一致：

1. **level 用自由滑条值**（默认 0），不是型号在制造者处登记的等级（fcs.def value[0]）。
   例如选了「刃之三」（登记等级 95）却以 level=0 保存 → 读档查不到 level 0 的型号 → 回退开顿城1号。
2. **`DefaultCompany()` 偏好 "Homemade"（自制）**：公司下拉框在"自动"时，即使用户选了
   刃之三，保存的也可能是 (Homemade, 刃之三, …) 的不匹配组合 → 读档同样回退。

修复（CreateWeaponRobust）：① company 必须真的包含所选型号，否则改用型号自己的制造者
（MfrOfModel）；② level 强制取制造者为该型号登记的等级（modelLevel），滑条仅作兜底。

## 二、根因（已从存档二进制证实）

Kenshi 中武器/装备的"品质"**不是一个数值**，而是两个 GameData 引用：

| 存档字段 | 含义 | 内存字段（KenshiLib） | 数据类型 |
|---|---|---|---|
| `base data sid` | 物品基础定义（如"武士刀"） | `RootObjectBase::getGameData()` | WEAPON / ARMOUR / ITEM |
| **`material sid`** | **材质/型号**（武器等级：开顿城1号、刃之三、铭刃…；护甲材质） | `InventoryItemBase::materialData`（0xC8） | **MATERIAL_SPECS_WEAPON** / MATERIAL_SPEC |
| **`company sid`** | **制造者**（开顿城废料刀、刃行者、铭刃…） | `InventoryItemBase::manufacturerData`（0xC0） | **WEAPON_MANUFACTURER** |
| `quality` (float) / `level` (int) | 品质系数 / 等级 | `quality`（0x11C）/ `getLevel()` | — |

存档实测样例：

```
material sid = "2311-clothes_v1.mod"     ← mod 提供的材质（mod 物品正常序列化）
company sid  = "917-gamedata.base"       ← 原版制造者
company sid  = "62167-rebirth.mod"       ← mod 提供的制造者
company sid  = ""                        ← 空 = 读档时回退默认（开顿城）
```

**结论：生成武器时如果只设置了内存中驱动显示的那个引用（或只给了 `levelOverride`），
而 `material sid`/`company sid` 其中之一为空或不一致，读档时游戏用默认制造者重建武器 → 开顿城1号。**

## 三、修复方案

### 方案 A（推荐）：createItem 时就把型号传进去

```cpp
#include <kenshi/Globals.h>
#include <kenshi/GameWorld.h>
#include <kenshi/RootObjectFactory.h>
#include <kenshi/util/hand.h>

// 1) 三样数据都按 GameData->name（英文名，FCS 里的名字）查
GameData* weapon = ou->gamedata.getDataByName("katana", WEAPON);                    // 武器基础
GameData* model  = ou->gamedata.getDataByName("Edge No.3", MATERIAL_SPECS_WEAPON);  // 型号=刃之三
GameData* maker  = ou->gamedata.getDataByName("Edgewalkers", WEAPON_MANUFACTURER);  // 制造者=刃行者

// 2) 关键：matData 传型号 GameData（MATERIAL_SPECS_WEAPON），不是制造者
hand h;
Item* w = ou->theFactory->createItem(weapon, h, nullptr, model, 0, nullptr);

// 3) 双保险：显式补齐两个引用（对应存档的 company sid / material sid）
if (w) {
    w->manufacturerData = maker;   // → company sid
    w->materialData     = model;   // → material sid
}
inv->addItem(w, 1, true, false);   // 放不进背包就掉地上，别销毁
```

> 注意：`getDataByName` 匹配的是 **GameData 内部英文名**（FCS 里显示的名字），
> 不是游戏内中文译名（中文来自汉化 locale）。调试时先把型号全列出来：
> ```cpp
> lektor<GameData*> list;
> ou->gamedata.getDataOfType(list, MATERIAL_SPECS_WEAPON);
> for (int i = 0; i < list.size(); ++i)
>     DebugLog("%s  [%s]", list[i]->name.c_str(), list[i]->stringID.c_str());
> ```
> 型号名大致为：Rusted junk / Rusting blade / Mid-Grade Salvage / Old refitted blade /
> Refitted blade / Catun No.1-3 / Mk I-III / Edge No.1-3 / Meitou（铭刃）。

### 方案 B：走游戏自己的创建路径

```cpp
// Character::generateWeapon(GameData* weapon, GameData* manufacturer)  RVA=0x621830
// 游戏给 NPC 配武器用的就是它，内部保证型号/制造者一致、可正常序列化。
// 缺点：型号在制造者范围内随机，不能直接指定「刃之三」。
Item* w = someCharacter->generateWeapon(weapon, maker);
```

### 方案 C（兜底）：copyItem 复制现成武器

`RootObjectFactory::copyItem(Item* from)` 会完整复制品质状态（社区经验：复制铭刃有效）。
可以先在世界中找/造一把正确的武器，之后生成都走复制。

## 四、验证步骤

1. 生成武器 → 立刻存档 → 读档，确认品质保持。
2. 二进制验证（可选）：用文本搜索存档 platoon 文件，确认该武器记录的
   `company sid` 与 `material sid` 均非空且指向目标 mod/base 的 SID。
3. 护甲同理：护甲品质（赝品~杰作）由 `materialData` 材质 + `quality` 决定，
   生成护甲时同样要设置 `materialData` 到正确的材质 GameData。

## 五、mod 武器/装备注意事项

- mod 物品的 SID 形如 `62167-rebirth.mod`，存档里正常保存——只要 GameData 引用本身
  来自 GameDataManager 的合并数据库（`ou->gamedata.getDataOfType` 枚举所得），序列化天然兼容。
- 风险点：读档时若对应 mod 被卸载，引用失效，物品同样会回退/消失——修改器 UI 可提示用户。
