# 医疗血量与形体保持（2026-10-09，2026-10-27 修订）

## 使用方式

医疗页增加「肢体与部位血量」「形体调节与保持」，原来的截肢、义肢操作保留在同页的折叠区。

### 部位血量

- 显示选中角色的实际 anatomy 列表，覆盖头、胸、腹、四肢，以及模组增加的部位。
- 「当前 / 上限」实时读取；目标血量、目标上限输入框是草稿。输入、回车、失焦都不会写游戏，只有「设定」「回满」按钮提交。「设定」同时提交两个目标值，「回满」只恢复当前血量。
- 当前血量可设为 `-目标上限～+目标上限`；负值按原版医疗逻辑处理。目标上限须大于 0 且不超过 1000000。断肢、粉碎肢体不可直接修改，需先恢复原生或安装义肢。
- 「回满」使用 `maxHealth()`，包含种族、年龄、HP 倍率与当前义肢磨损。不会把所有种族一律设为 100，也不会清掉义肢磨损。
- 修改清除该部位的钝伤及临时修补值，并把已有绷带量限制在剩余伤口范围内；不修改其他部位、血液、饥饿、死亡标志或全身昏迷计时器。因此回满一只手不会自动治愈失血或复活角色。
- 数值非有限、空输入、越界或部位身份发生变化时拒绝写入。角色切换时清理输入草稿；「刷新」从最新血量重新填入草稿。

目标上限是界面显示的**实际上限**。实现按 `age * _maxHealth * HPMult - wearDamage` 反算并写入基础字段 `_maxHealth`，保留种族、年龄倍率与义肢磨损的后续影响；不会直接把实际上限字段写死，也不会清除磨损。部位「回满」不修改全身血液。

### 全身血液

- 医疗页在部位表格上方独立显示 `当前血液 / getMaxBlood()`，可输入目标值后「设定」，或直接「回满」。
- 目标范围为 `-getMaxBlood()～+getMaxBlood()`，以保留原版失血昏迷、死亡等状态所使用的负血值语义；非法、非有限或越界输入不写入。
- 写入 `MedicalSystem::blood` 后调用 `reassessCollapseMode(true, false)` 重新评估昏迷状态并核对读回值。血液与部位伤势独立：回血不治疗部位，部位回血也不补全身血液。
- 「刷新」同时重取全身血液和各部位输入草稿；日志记录 `KenshiTrainer: blood ... result=ok/failed`。

### 义肢部位兼容

- 每个肢体下拉只列出明确对应该部位的型号，安装前再次校验；无法识别左右侧或手臂/腿类型的项目不再默认显示给四肢，也不能安装。
- 优先从本地化名称识别：英文 `left/right` 与 `arm/leg`，中文 `左/右` 与 `臂/腿`，避免把含义不明确的 `side=0/1` 错当成完整四肢编号；名称不明确时才尝试 `limb type`、`limb`、`which limb` 的 0～3 值。名称标记由 `tools/gen_prosthetic_names.py` 生成到纯 ASCII 的 `src/ProstheticNames.h`。
- 四个编号依次是左臂、右臂、左腿、右腿。未识别模组义肢会写入 `prosthetic compatibility unknown` 日志；如需支持，应根据实际 GameData 补充明确映射，而不是放开跨部位安装。

### 形体保持

1. 选中人形角色。模型仍在加载时也可以先配置，数值会排队到游戏后续外观更新。
2. 「锁定当前外形」捕获当前三个外观倍率；或用三个滑条调节后点击「应用数值并保持」。Ctrl+点击滑条可直接输入，范围为 0～100。
3. 体格控制粗壮程度，肌肉控制肌肉外观，消瘦值越高越瘦。这些数值是外观倍率百分比，**不是力量等级**。
4. 「保持外形」取消后，下一次外观更新恢复由游戏属性自动计算。

「锁定当前外形」不是只应用一次：它持续覆盖游戏的三个外观计算输出。之后力量、相关技能或营养状态变化时，角色属性仍正常改变，但体格、肌肉和消瘦外观保持锁定值；取消锁定后才恢复游戏自动计算。

锁定按角色外观对象分别记录。可以给多人设置不同外形；切换角色、关闭面板后仍然生效。数据仅保留在本次外观对象生命周期内，**角色卸载、读档、重启后需重新设置**；不写入游戏存档，也不把角色指针保存进 INI。

修改排队给游戏自己的外观更新流程；暂停游戏时需恢复运行，等待下一次外观更新。渲染 UI 不主动调用 OGRE 骨骼、材质接口。

动物不提供此功能。人类、沙克族、蜂巢族、骨人及模组人形种族使用相同 `AppearanceHuman` 外观系统时可设置，但具体视觉效果由种族模型、骨骼和材质决定。模型加载、剥皮或机械外观不再隐藏配置项。功能锁定属性驱动的体型，不冻结装备、发型、伤口、动作或整个人物模型。

## 本地二进制核对

分析对象为已安装的 `RE_Kenshi/Kenshi_x64.exe`，Steam 1.0.65 兼容版。函数从本机 KenshiLib 导出桩索引映射至 `RE_Kenshi/RVAs/Steam_1.0.65.br`，未使用头文件注释中的旧 RVA。

| 入口 | 实际 RVA | 已核对行为 |
|---|---|---|
| `AppearanceHuman::updatePhysiqueMuscleMults` | `0x52B1E0` | 写出 bulk、muscle、skinny 三个倍率 |
| `AppearanceHuman::updatePysiqueFromStats` | `0x530D90` | 先计算倍率，再更新肌肉贴图及玩家骨骼比例；保留游戏原有缓存更新 |
| `AppearanceHuman::updateProportions` | `0x52DC30` | 使用上述倍率与原本捏脸数据更新骨骼比例 |
| `AppearanceHuman::_NV_periodicUpdate` | `0x532E50` | 经跳板进入 `updatePysiqueFromStats` |
| `AppearanceBase::_DESTRUCTOR` | `0x5317E0` | 真实销毁清理入口 |
| `HealthPartStatus::maxHealth` | `0x296C30` | `age * _maxHealth * HPMult - wearDamage` |
| `HealthPartStatus::updateDerivedHealths` | `0x643190` | `(flesh - fleshStun + juryRigging) / maxHealth()` |
| `MedicalSystem::getMedicalGUIData` | `0x889A20` | 部位血量数字取 `flesh - fleshStun`，条形信息另包含绷带与临时修补值 |

体格不仅受力量影响，还读取武器、护甲锻造技能；肌肉读取敏捷、武术、游泳、运动，以及科学、烹饪的抵消项。归一化辅助函数 `0x9B0090` 为 `(value - low) / (high - low)`，结果被限制到 0～1。消瘦倍率是单独的输出。因此仅屏蔽力量引起的变化不能完整保持外形。

`AppearanceHuman` 的三个输出字段为 `bulkMult@0x1A0`、`muscleMult@0x1A4`、`skinnyMult@0x1A8`。实现使用头文件字段和 KenshiLib 动态解析；上表 RVA 只作研究记录，不硬编码进插件。

**析构内联陷阱**：人形 vtable 析构槽经 `0x130D4` 跳到 deleting destructor `0x544930`。它内联派生析构，直接调用 `0x30170 -> AppearanceBase::_DESTRUCTOR`，没有调用 `AppearanceHuman::_DESTRUCTOR@0x532E30`。因此清理钩子必须设在基类；仅钩派生析构会遗漏常规虚销毁路径，留下悬空的角色外观键。

`tools/analyze_medical_physique.py` 使用本机 Python 与 capstone 进行只读反汇编；支持 MSVC 链式 unwind 记录，避免只得到函数保存寄存器的开头一段。脚本默认本机安装路径，只是研究工具，不参与插件构建。

## 实现约束

- `PhysiqueControl.cpp` 管理三个钩子：原版倍率计算后覆盖外观输出、游戏外观更新后完成待提交的骨骼刷新、外观基类析构后移除记录。
- 始终调用原来的倍率计算；未锁定角色不覆盖结果。**从不写 CharStats，也不临时把属性换成假值**。锁定与解锁都不写饥饿或其他医疗状态。
- SRW 锁保护 UI 与游戏线程共享的角色记录；调用游戏前释放锁。revision 保证处理中的旧请求不能清掉刚提交的新请求。
- 只有三个钩子全部安装成功才启用。部分安装时保持原版输出；故障记录一次并停用覆盖。
- `KT_NOPHYSIQUE` 仅跳过形体钩子，用于排查；原有 `KT_NOHOOK` 与 `mods.cfg` 启动休眠保持生效。
- 新文案通过 `tools/gen_health_physique_strings.py` 生成，`ChineseStrings.h` 仍为纯 ASCII 的 UTF-8 hex 表。

## 验证状态与实机清单

初版已完成 MSVC v100 Release|x64 构建、兼容版函数反汇编及 DLL 导入核查。2026-10-27 根据实机反馈放宽体型面板限制、增加部位上限编辑、加入全身血液编辑并严格限制义肢部位兼容；本次修订仍需游戏内回归验证。

实机需逐项确认：

1. 未选角色不崩溃；中英文页签、折叠区和输入框可用。
2. 原生与义肢分别设定血量及上限；伤势中含钝伤、绷带、临时修补时，输入值与游戏数字一致。100/125/200 等不同种族上限及磨损后的义肢回满正确；提高、降低上限后实际读数正确，年龄/种族倍率与磨损仍生效。
3. 空值、越界、负值及断肢操作符合说明；分别验证全身血液设定/回满与部位设定/回满，二者不互相治疗，且不消除饥饿。
4. 锁定后提高或降低力量、敏捷、运动等技能：属性改变，体格与肌肉外观保持。单独验证三个滑条的 0、50、100 与小数值。
5. 取消锁定后恢复正常外观；甲乙角色分别设置，切换选中与关闭面板后互不影响。
6. 暂停提交、恢复运行、快速连续修改、换装备、义肢替换后仍正确刷新；读档/卸载后旧记录清理，不串角色。
7. 人类男女、沙克、蜂巢、骨人、剥皮及兼容模组人形种族分别观察配置项与效果；动物提示不支持。原生肢体直接安装义肢、替换旧义肢均不再需要先截肢。左右臂/腿下拉只能看到对应型号，尝试绕过界面状态安装不匹配项目也会被拒绝。
8. 回归已有属性、物品、金钱、改名、截肢义肢、建筑与经验功能。

日志入口：`KenshiTrainer: physique hooks ready (3/3)`、`physique queued`、`physique applied`、`physique released on appearance destruction`、`part health ... result=ok/failed`。有异常时提供 `RE_Kenshi_log.txt` 及 DLL 旁的 `KT_*.txt`。
