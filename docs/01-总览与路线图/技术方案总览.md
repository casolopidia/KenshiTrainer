# Kenshi 内置修改器 · 技术方案总览

> 目标：游戏内置修改器——修改选中角色属性、向选中角色背包生成物品/装备（含 mod 新增物品），现代化 UI，游戏内左上角入口按钮。

## 一、核心技术路线（已确定）

Kenshi 没有官方 Lua/脚本 API。要在**游戏内**实现带 UI 的修改器，社区唯一成熟方案是：

**RE_Kenshi（代码注入框架） + KenshiLib（逆向重建的 C++ API SDK）**

- RE_Kenshi 以 Ogre 插件方式注入游戏进程（`Plugins_x64.cfg` 中加 `Plugin=RE_Kenshi`），负责加载 mod 文件夹里的插件 DLL。
- 我们的修改器就是一个 **KenshiLib 插件 DLL**，放在 `Kenshi/mods/<修改器名>/` 下，通过 `RE_Kenshi.json` 声明加载。
- 游戏 UI 基于 **MyGUI**（Ogre3D 的 GUI 库），插件可以直接创建游戏原生风格的窗口和按钮。
- GPL-3.0 许可证：使用 KenshiLib 的插件一般也需以 GPLv3 发布。

### 目标版本

- RE_Kenshi 基于 Kenshi 1.0.65 逆向；最新版 v0.3.5（2026-08-26）的安装器支持 1.0.68（会自动生成兼容可执行文件）。
- 插件编译：必须用 **VS2019+ 外壳 + Visual C++ 2010 (v100) x64 工具链**，Boost 1.60.0，只能用 RELEASE 模式。

## 二、功能到 API 的映射（已从 KenshiLib 头文件确认）

头文件已下载至 `reference/KenshiLib_include/`，以下签名均来自 `Include/kenshi/*.h`（RVA 为 1.0.65 地址，由 KenshiLib 做版本无关封装）。

| 功能 | 关键 API | 头文件 |
|---|---|---|
| 获取当前选中角色 | `ou->player->selectedCharacter.getCharacter()` | `Globals.h` / `PlayerInterface.h` |
| 读取/修改属性 | `CharStats::getStatRef(StatsEnumerated)` 返回 `float&`，直接赋值即修改；`getStat()` 读取 | `CharStats.h` |
| 属性枚举（力量/敏捷/武术/潜行……共 39 项技能 + 衍生属性） | `StatsEnumerated`（`STAT_STRENGTH` … `STAT_END`，及 `_MaxCarryWeight` 等） | `Enums.h` |
| 枚举全部物品定义（含 mod） | `GameDataManager::getDataOfType(lektor<GameData*>&, itemType)` —— 运行时数据已合并所有启用 mod | `GameDataManager.h` |
| 按名字/SID 查物品定义 | `getData(sid, category)` / `getDataByName(name, category)` | `GameDataManager.h` |
| 创建物品实例 | `RootObjectFactory::createItem(GameData* gd, const hand&, GameData* weaponMesh, GameData* matData, int levelOverride, Faction*)` | `RootObjectFactory.h` |
| 放入背包 | `Inventory::addItem(Item*, int quantity)` / `_addItem(item, x, y)` | `Inventory.h` |
| 物品栏结构 | `Character->inventory`（Item 类型 `ITEMTYPE_BACKPACK` 即背包） | `Character.h` / `Item.h` |

### 关键洞察：mod 物品天然被覆盖

游戏启动时 GameDataManager 会把**所有启用的 mod 数据合并**进运行时数据库。因此用
`getDataOfType(list, itemType)` 枚举物品时，mod 新增的武器/装备/物品自动包含在内，
无需单独解析 .mod 文件。—— 这正是本方案相比"外部存档修改器"的最大优势。

## 三、UI 方案

### 游戏内 UI = MyGUI（已确认可行）

KenshiLib_Examples 里的 **KillButton 示例**（源码已存 `reference/KenshiLib_Examples/KillButton/`）
演示了完整模式：

1. Hook `TitleScreen` 构造函数（保证在 UI 线程同步创建控件，MyGUI 非线程安全）；
2. `MyGUI::Gui::getInstancePtr()->createWidgetReal<MyGUI::Window>("Kenshi_WindowCX", ...)` 创建游戏原生皮肤窗口；
3. `createWidgetReal<MyGUI::Button>("Kenshi_Button1", ...)` + `eventMouseButtonClick += MyGUI::newDelegate(...)`。

### "现代化 UI"的实现路径（二选一或结合）

- **路径 A：纯 MyGUI 自绘皮肤**。MyGUI 支持自定义 skin/texture，可做出扁平化现代风格。
  优点：与游戏渲染管线完全兼容，示例现成。缺点：布局能力弱，复杂界面工作量大。
- **路径 B：MyGUI 做入口按钮 + 内嵌 CEF/ImGui 面板**。左上角入口按钮用 MyGUI（KillButton 模式），
  点击后展开自绘面板。RE_Kenshi 自身设置界面（Options→Mods→RE_Kenshi Settings）即此思路。
  需评估渲染 hook 成本。**建议先用路径 A 完成 MVP，再升级。**

### 左上角入口按钮

Hook `MainBarGUI`（`gui/MainBarGUI.h`）或标题/主界面初始化点，在左上角创建一个
小按钮控件，点击切换修改器主窗口显示/隐藏。快捷键（如 F11）作为辅助入口。

## 四、工程结构规划

```
mods/KenshiTrainer/            → 最终安装到 Kenshi/mods/ 下
├── RE_Kenshi.json             → { "Plugins": ["KenshiTrainer.dll"] }
├── KenshiTrainer.mod          → FCS 生成的空 mod 定义（让插件出现在 Mods 列表）
└── KenshiTrainer.dll          → 编译产物
src/
├── Plugin.cpp                 → startPlugin() 入口、hook 安装
├── ui/                        → MyGUI 界面（入口按钮、主面板、属性页、物品生成页）
├── features/StatsEditor.cpp   → 属性读写
├── features/ItemSpawner.cpp   → 物品枚举、搜索、生成
└── data/ItemCatalog.cpp       → GameDataManager 枚举 + 缓存
```

## 六、开发里程碑

1. **环境搭建**：装 RE_Kenshi，编译运行 HelloWorld + KillButton 示例 ✅（验证管线）
2. **MVP-1 属性修改**：左上角按钮 + 属性面板（选中角色 39 项技能读写）
3. **MVP-2 物品生成**：物品目录枚举（含 mod）+ 搜索 + 生成到选中角色背包
4. **UI 升级**：现代化皮肤/面板打磨
5. **健壮性**：存档兼容、异常保护、卸载清理

## 七、风险与注意事项

- **线程安全**：MyGUI 只能在 UI 线程访问（KillButton 用 TitleScreen 构造 hook 解决）。
- **Hook 规范**：必须用 KenshiLib 的 `AddHook`（支持多插件共存），禁用第三方 detour 库。
- **Smart App Control**（Windows）可能导致插件加载失败，需在文档中提示用户。
- **版本绑定**：KenshiLib 对 1.0.65 支持最完整；1.0.68 需 RE_Kenshi 安装器做兼容处理。
- 修改属性直接用 `getStatRef()` 写值即可持久生效；但技能经验/升级机制可能回写，需实测。
